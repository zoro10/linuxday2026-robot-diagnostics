# PULSE-1 — Diagnostic Platform v0.4

Data: 10 ottobre 2026
Evento: LinuxDay 2026 — 24 ottobre

## Architettura

Sistema A:
- Gazebo Harmonic
- ROS 2 Jazzy
- PULSE-1, sensori e controller

Sistema B:
- Collector Python nativo Ubuntu
- Robot Health e Platform Health
- JSON diagnostico in runtime/
- Diagnostic API Python in Docker
- Nginx come reverse proxy
- Applicazione PHP e MariaDB esistenti

Il sistema A funziona senza il collector.

## Avvio

Terminale robot:

    cd ~/vmdiag-app
    ./scripts/start_demo.sh

Terminale collector separato:

    cd ~/vmdiag-app
    ./scripts/start_collector.sh

Servizi Docker:

    cd ~/vmdiag-app
    docker compose -f compose.yaml -f compose.api.yaml up -d --build

## Endpoint

http://127.0.0.1:8080/api/health
http://127.0.0.1:8080/api/status
http://127.0.0.1:8080/api/robot
http://127.0.0.1:8080/api/platform
http://127.0.0.1:8080/health.php

## Comportamento verificato

- Collector attivo: telemetria FRESH
- Collector fermo oltre 10 secondi: STALE
- Telemetria STALE: Robot Health UNKNOWN
- Collector riavviato: recupero automatico
- L'API resta HTTP-raggiungibile durante la perdita del collector
- Il JSON viene montato nell'API in sola lettura

## Limitazioni

- Il collector non viene ancora avviato automaticamente.
- Il web PHP esistente non è ancora la dashboard diagnostica.
- I 20 punti API vengono assegnati durante l'elaborazione HTTP.
- La resilienza dell'avvio completo dopo reboot resta da collaudare.
- Nessuna autenticazione HTTP: non esporre la porta 8080 a Internet.
- Dashboard e test di guasto sensori ancora da implementare.

## Ripristino completo

Dopo un riavvio della VM:

    cd ~/vmdiag-app
    ./scripts/restore_demo.sh

Il ripristino usa Docker Compose e due sessioni tmux indipendenti: pulse1 e diagnostics.
